# 《面向 AI 原生系统的智能运维》课程级优化与授课指南

## 1. 任务合同

- 目标：将 17 讲完整研究型课件转化为可在每讲 2 学时内执行的教学路线，同时保留论文、实验结果、工程案例和拓展材料。
- 受众：计算机及相关专业研究生，默认具备操作系统、计算机网络、分布式系统和机器学习基础。
- 核心产物：每讲的主问题、独有产物、必讲内容、选择讲解内容、案例/实验和跨讲边界。
- 非目标：不以机械压缩页数替代教学编辑；不删除论文的实验条件、结果解释和失效边界；不把内部项目文件名写进正文。
- 课堂容量：每讲 110--120 分钟，推荐 60--80 个主讲页面；完整 PDF 同时承担讲义和课后阅读材料。

## 2. 全课程主线

课程只维护一条递进链：

> AI 原生系统及其失败机制 → 产生可关联的观测证据 → 检测异常并形成事件 → 组织候选与因果证据 → 把诊断接入受控工作流 → 建设平台、对象、事件和智能体 → 完成可验证调查。

每讲只回答一个主问题，并交付一个后续章节可以直接消费的产物：

| 周次 | 主问题 | 本讲独有产物 | 不重复讲解的内容 |
|---|---|---|---|
| 01 | AI 原生系统由什么组成？ | 六层系统地图与课程共同语言 | 不深入具体检测/RCA 算法 |
| 02 | 这些系统如何失败？ | 故障语言与故障模式清单 | 不展开采集系统实现 |
| 03 | 应采集什么信号？ | 指标模型、OTel 与时序底座 | 日志/Trace 只讲定位，不讲细节 |
| 04 | 如何还原一次请求？ | 日志—Trace—上下文证据链 | 不重复 Prometheus 基础 |
| 05 | 如何观察训练、推理、RAG 与 Agent？ | GPU/Token/质量/成本统一调用链 | 不重讲通用三支柱 |
| 06 | 何时偏离正常？ | 异常分数、阈值、事件级评测与告警状态 | 不做根因判定 |
| 07 | 谁最值得检查？ | 候选排名与支持/反证证据表 | 不宣称相关性等于因果 |
| 08 | 什么证据支持因果？ | 因果图、干预与反事实验证方案 | 不重复候选生成算法 |
| 09 | Agent 如何进入运维工作流？ | 有状态、可审批、可回放的工作流 | 不讲企业转型与平台采购 |
| 10 | 如何把试点变成组织能力？ | 场景阶段门、责任模型和转型路线 | 不重复 Agent 算法细节 |
| 11 | AIOps 平台怎样承载这些能力？ | 数据/控制平面、对象/事件合同与平台蓝图 | 论文只服务平台接口设计 |
| 12 | 大模型怎样进入平台控制面？ | 模型网关、RAG、Agent Runtime、评测和安全架构 | 不实现具体 RCA Agent |
| 13 | 如何实现一个 RCA Agent？ | Task Envelope、状态机、工具契约与 Verifier | 不重复平台总架构 |
| 14 | 如何把自然语言编译成运维流程？ | Intent Contract、Workflow DSL、审批/回滚/Oracle | 不重复 RCA 调查策略 |
| 15 | 系统世界里有哪些对象和关系？ | Canonical Object、实体对齐、时态对象图 | Profiling 只用于建立对象证据 |
| 16 | 这些对象发生过什么？ | Canonical Event、Episode 与对象级事件记忆 | Merge/Link 与 RCA 严格区分 |
| 17 | 现在应该查什么，怎样证明？ | Investigation Trace、竞争假设、主动查询与停止条件 | 复用前述合同，不重新搭平台 |

## 4. 论文进入课堂的统一模板

每篇论文至少回答六个问题，避免变成论文名单：

1. 问题：现有方法为什么不够？
2. 机制：系统新增了什么观测点、状态或算法？
3. 结果：在哪个数据集、集群或负载条件下改善了什么指标？
4. 解释：结果为何成立，最关键的设计是什么？
5. 边界：开销、假设、数据依赖与外部有效性是什么？
6. 落点：它为本讲的对象、事件、工具或 Evidence Bundle 增加什么字段？

同一论文可以出现在多讲，但必须承担不同角色。例如：

- TELLER：第 3 讲用于说明跨层观测；第 5 讲用于请求—GPU 关联；第 11 讲用于平台 Evidence Bundle；第 17 讲仅作为可调用诊断工具。
- AgentChaos：第 2 讲用于故障模式；第 8 讲用于干预与验证；第 13 讲用于 Agent 故障注入评测。
- Neutrino/FLARE/Aegis/StriaTrace：第 15 讲建立细粒度对象与关系证据；第 16 讲转译为事件字段；第 17 讲只讨论 Agent 何时调用。

## 5. 两学时节奏模板

- 0--10 分钟：真实问题、上一讲产物、本讲输入输出。
- 10--35 分钟：概念和系统模型，建立共同语言。
- 35--65 分钟：核心机制或算法，必须包含小算例或执行轨迹。
- 65--75 分钟：休息或课堂检查点。
- 75--95 分钟：1--2 篇论文的机制、结果和边界。
- 95--110 分钟：贯穿案例或实验设计。
- 110--120 分钟：结论、反例、下一讲接口和课后阅读。

当完整课件超过 90 页时，不按页码平均加速。优先保留问题、机制、结果、边界、案例和结论页；将同类产品对比、更多论文、实现清单和参考页放入课后拓展。

## 6. 视觉与引用规则

- 封面统一为“陈鹏飞｜中山大学”；正文不使用“某教授团队”等身份性标题，改用论文或系统名称。
- 正文不出现内部项目执行文件名；系统原型、脱敏案例、正式论文和课程教学重绘必须明确区分。
- 不使用完整第三方 PPT 页面截图。只使用论文独立图、图表、软件独立界面或经教学重绘的架构图。
- 每张外部图片必须能看清完整内容，并在本页给出中文阅读顺序、关键机制和局限。
- 结果数字必须保留实验条件；不把单次实验、Demo 或项目快照外推为生产 SLA。

## 7. QA 门槛

- XeLaTeX 连续编译两次，无 fatal error。
- 对 overfull box、标题换行、表格裁切、图片裁切、引用过小逐项检查。
- PDF 首页必须包含课程名、讲次、陈鹏飞、中山大学。
- 搜索正文，确保无“项目执行情况”、API key、TODO、占位符或未核实结论。
- 视觉检查完整 PDF contact sheet，并对公式、密集表格、外部图片和最后一页做高分辨率抽检。
