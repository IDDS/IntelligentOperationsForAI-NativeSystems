# 课程概念关系图：模型辅助分析记录

## 目标

本次修订将图的语义从“系统组件拓扑/对象图”改为“课程内容之间的关系图”。节点代表可讲授、可评估的课程概念、方法或论文案例；边代表教学依赖、方法作用或知识闭环，不表示线上系统的数据流。

## 外部模型审阅

- DeepSeek：建议将 17 周课程压缩为 7 个知识域：AI 原生对象与故障语言、可观测性工程、异常检测与告警压缩、候选定位与因果诊断、Agent 化运维执行、平台化与运行时治理、事件记忆与知识闭环。
- Qwen：建议采用“系统概念 → 证据采集 → 异常检测 → 因果诊断 → AI 治理执行 → 验证与知识沉淀”的 6 阶主线，并明确使用先修、观测、检测、定位、诊断、治理、验证、沉淀、案例等关系。

两份分析的共同结论是：图中应突出学生的认知路径，而不是把 Model、GPU、Agent 排成一条架构数据流。

## 综合后的图模型

主线节点：

`AI 原生系统` → `观测证据` → `检测与定位` → `因果诊断` → `Agent 化运维` → `运行时治理` → `验证与知识闭环`

知识域与周次：

| 知识域 | 周次 | 代表概念 |
|---|---:|---|
| AI 原生系统基础 | W01–02 | 故障语言、SLO/质量、训练/推理/Agent 生命周期 |
| 可观测性基础设施 | W03–05 | 指标时序、结构化事件、OTel 调用链、Token/TTFT、Langfuse |
| 异常感知与压缩 | W06–07 | 异常检测、告警压缩、候选故障域、调用链剪枝 |
| 根因分析与诊断推理 | W08 | RCA 假设、因果图/SCM、反事实验证、多源证据融合 |
| AI 驱动的运维执行 | W09–10、W14 | ReAct、工具/MCP、多智能体协作、记忆、Workflow、RCA Agent |
| 全栈运行时治理 | W11–13、W15 | LLM Serving、GPU/Kernel、控制面/数据面、Chaos、Guardrail |
| 运维知识闭环 | W16–17 | 评测/Oracle、回放、事件记忆、运维知识图谱 |

## 关系类型

- 橙色粗边：先修/递进主线。
- 蓝色：观测/采集；绿色：检测/压缩；红色：定位/诊断；紫色：治理/执行；青色：验证/回放；灰色虚线：沉淀/反馈。
- 紫色虚线胶囊：论文或工业案例锚点，案例附着在概念节点旁，不占用主线的中心位置。

## 视觉设计约束

1. 采用 Neo4j/点—边图的语义，但用课程知识域作为轻量背景分组，避免把背景框误读为系统组件边界。
2. 中央主线只保留 7 个高层概念；细粒度概念挂在对应知识域，避免所有节点都挤在一张无层次的力导向图上。
3. 论文/案例使用虚线胶囊并标注为案例锚点，避免直接截取整页 PPT，也避免把案例误认为课程主概念。
4. 图底部用“课程主线、工程化落地、阅读论文的方法”三个提示卡补充讲授逻辑，而不是增加新的节点和边。

## Graphviz 两阶段生成

用户进一步要求先生成稳定的节点—边图，再做视觉集成。为此新增 `course-knowledge-graph-graphviz-v11.dot`：节点、关系类型和课程周次均在 DOT 源文件中定义，由 Graphviz 自动完成布局、折线和箭头端点计算。`graphviz-v11.svg/png/pdf` 是第一阶段的可检查结果；只有在关系结构确认后，才继续做背景、标题和宣传版式集成。

v12 在 Graphviz 源文件中为每个知识域增加“要回答的问题”，为关键节点增加一句教学解释，并在图标题中加入课程资料仓库：`github.com/IDDS/-IntelligentOperationsForAI-NativeSystems`。海报同步更新为 `course-poster-light-v6.*`。

由于 v12 横向跨度仍偏大，v15 改为 Graphviz 的上下分层布局，减少横向空白和跨图长边；同时保留自动箭头、知识域问题说明、节点教学解释和 GitHub 地址。v15 是当前推荐的图谱版本。
